# Kotoba — Local Translate

ローカルで動かす PLaMo 3 Translate の OpenAI 互換エンドポイントを使う、個人用の Firefox 拡張です。ビルドなしで `extension/` を読み込めます。

## Firefox に読み込む

1. Firefox で `about:debugging#/runtime/this-firefox` を開きます。
2. 「一時的なアドオンを読み込む」から、このリポジトリの `extension/manifest.json` を選びます。
3. ツールバーの Kotoba →「接続設定」で、起動中の翻訳サーバを設定します。

一時的なアドオンは Firefox 終了時に外れます。再起動後は読み込み直してください。署名や配布の仕組みは含めていません。

更新時は拡張に加えて、翻訳するページも再読み込みしてください。ページ内に古いスクリプトが残っている場合は、ポップアップに「ページを再読み込み」を表示します。ZIPから読み込んでいる場合は、更新したZIPを読み込み直す必要があります。

開発用に別プロファイルの Firefox を起動する場合：

```sh
npm ci
npm start
```

## 接続設定

| 設定 | 初期値 |
| --- | --- |
| エンドポイントURL | `http://127.0.0.1` |
| ポート | `8000` |
| Chat Completions パス | `/v1/chat/completions` |
| APIキー | 空欄 |
| モデル名 | `plamo-translate` |
| 翻訳パラメータ形式 | トップレベル（依頼のbody形式） |
| 同時リクエスト | **全タブ共通で1**（設定で1〜8） |
| 入力の分割上限 | 6000トークン（設定で128〜24000） |
| サーバーのコンテキスト長 | 32768トークン（入力＋出力。サーバー設定と合わせる） |
| 出力上限 | **`max_tokens: 8096`** |
| タイムアウト | 180秒（設定で変更可能） |
| 翻訳キャッシュの保存期間 | 30分（0〜1440分、0で無効） |

上の例では `http://127.0.0.1:8000/v1/chat/completions` に送信します。URLにはサーバのベースURL、パスにはAPIのパスを入れてください。ベースURLにパスがあれば、その後ろにAPIパスを連結します。ポート欄を空にするとURL内のポートを使います。

APIキーを設定すると `Authorization: Bearer <APIキー>` を付けます。入力時の `Bearer ` 接頭辞は取り除くため、キーだけでも入力できます。接続先以外へのリダイレクトは追跡しません。APIキーを含む設定は `browser.storage.local` に保存し、Webページやcontent scriptには渡しません。

### API形式

初期値は依頼されたトップレベル形式です。

```json
{
  "model": "plamo-translate",
  "messages": [{ "role": "user", "content": "Text to translate." }],
  "context": "This text is from a web page on https://example.com. Translate it as part of the website, preserving the meaning and natural flow of complete sentences.",
  "form": "",
  "source_lang": "en",
  "target_lang": "ja",
  "max_tokens": 8096,
  "stream": false,
  "temperature": 0,
  "use_glossary": false
}
```

`context` はWebサイトの文章を翻訳する旨と、翻訳対象ページの **origin（scheme + domain + ポート）** を含みます。HTMLを含む段落では、段落全体の自然な語順を保ち、タグ・リンクのID・コードを保持する条件も加えます。パス・クエリ・ページタイトルは渡しません。原文言語の「自動判定」では `source_lang` を省略します。

公式の MLX `serve.py` / llama.cpp / vLLM のチャットテンプレートを使う場合は、設定の「chat_template_kwargs」を選びます。`source_lang`、`target_lang`、`context`、`form` を `chat_template_kwargs` に入れ、公式例のstopトークンを指定します。専用翻訳モデルなので、翻訳の指示を `system` メッセージに入れません。

参照： [PLaMo 3 Translate 公式モデルカード](https://huggingface.co/pfnet/plamo-3-translate-8b-GGUF#translating-with-the-api)。公式では `max_tokens` は訳文の生成上限であり、入力と出力の合計はサーバのコンテキスト長にも収める必要があります。入力上限6000と出力8096に加え、文脈・辞書・制御情報も収めてください。拡張は指定したコンテキスト長から出力8096・制御用512・文脈と辞書のバイト数を予約し、入力上限を必要に応じて下げます。サーバー自身のコンテキスト長は変更しません。既存の保存済み入力上限は更新後も保持します。

## 使い方

- **ページ翻訳**：ツールバーで原文・訳文の言語を選び「ページを翻訳」。言語はそのページの状態として保持します。初期値だけ接続設定で指定できます。
- **右クリックで操作**：ページの余白を右クリック → Kotobaの「ページ翻訳／停止」「原文に戻す」でも操作できます。ページ翻訳はトップフレームが対象で、ページで選んだ翻訳言語を使います。文章を選択して右クリックした場合は、従来どおり選択翻訳を使えます。
- **まとめて翻訳**：既定でオン。同じ記事・セクション・表・メニュー内の段落を、ID付きの短い`p`要素で囲んでまとめます。最初の送信は最大8単位・約1800入力予算、その後は最大64単位・設定した入力上限です。段落の位置は個別に保持し、同じ表の行・リスト項目は予算に収まる範囲で同じ送信に入れます。隣接する段落は文脈に使い、内容を段落間で移動することは禁止します。応答のマーカーと各段落のHTML構造を検証してから反映します。構造が壊れたバッチは段落単位で再試行し、そのページ翻訳中の以後のバッチ試行も止めて再送の連鎖を避けます。設定の「同じ記事・表・メニューの段落をまとめる」をオフにすると従来の小さなバッチに戻せます。「複数の段落をまとめて翻訳」自体もポップアップ・設定でオフにできます。
- **原文表示**：訳文にマウスを280ms重ねると、対象の段落を薄い水色で強調し、原文を表示します。同じ段落内では表示を維持し、ポップオーバー内へ移動して原文を選択できます。「固定」で表示を維持できます。外側のクリック・スクロール・Escapeで閉じます。ツールバーでホバー表示を切り替えられます。
- **選択翻訳**：文章を選択し、右クリック →「選択したテキストを翻訳」。ツールバーの「選択範囲を翻訳」でも使えます。選択範囲の近くに結果を表示し、パネルで言語を変更して再翻訳できます。選択翻訳はページの文章を差し替えません。
- **進捗**：ツールバーとページ内パネルで、進捗率・完了段落数・経過秒数を表示します。進捗率は翻訳対象の原文文字数に対する処理済み文字数で、長文の分割リクエストの完了も反映します。バーの斜線部分は現在処理中の範囲です。処理中・未着手の段落数に加え、順番待ち・入力の計測・翻訳サーバーの応答待ちと、それぞれの経過秒数を表示します。トークン生成の進捗率ではありません。ページ内パネルを閉じても翻訳は続きます。
- **停止**：処理中・待機中のAPIリクエストを中断し、遅れて返った訳文の適用を防ぎます。
- **翻訳の履歴**：ポップアップの「翻訳の履歴」または設定画面の「翻訳の履歴と処理速度を見る」で、キャッシュに残っている翻訳を確認できます。
- **原文に戻す**：翻訳部分を復元します。サイト自身が更新した箇所には古い原文を上書きしません。
- **追加で読み込まれた文章**：再度「ページを翻訳」を押してください。表示中の翻訳済みノードはそのままに、新しい文章や、開いた折りたたみ領域の内容を処理します。原文に戻した後の再翻訳では、期限内のキャッシュがあれば再利用します。

### 翻訳辞書

ポップアップの「翻訳辞書」から現在のドメインを、設定画面の「翻訳辞書を編集」から全体共通の辞書を開けます。適用範囲を選び、「用語を追加」で原文言語・訳文言語・原語・訳語を入力してください。ドメインはホスト名の完全一致で、サブドメインは別扱いです。HTTP/HTTPSとポートは区別しません。

- 全体共通にドメイン別の用語を重ね、同じ原語はドメイン別を優先します。同じ範囲では原文言語を指定した項目を優先します。原文の「すべて」は自動判定を含む全言語に適用し、原文を自動判定にした翻訳では「すべて」の項目だけを使います。訳文言語は常に一致する項目だけを使います。原語の大文字・小文字は区別します。逆方向の辞書は別途登録してください。
- 用語は直接編集でき、個別削除と選択した範囲の全件削除ができます。「保存」で反映し、「変更を破棄」で最後に保存した状態へ戻せます。未保存で画面を閉じる際は確認を表示します。空欄・重複・上限超過は保存できません。
- 全体共通・各ドメインそれぞれ100件、合計500件、最大20ドメイン。原語・訳語は各100文字まで。同じ翻訳に適用する辞書はAPI用JSONで6000 UTF-8バイトまでに制限し、超過時は切り捨てず保存エラーを表示します。空のドメインは保存しません。
- 辞書はこのFirefoxのローカル設定に保存し、適用する用語だけを翻訳APIの `glossary` に渡します。トップレベル形式では `use_glossary: true`、テンプレート形式では `chat_template_kwargs.glossary` を使います。ページの本文を事前置換せず、モデルへ訳語の指定として渡すため、採用はモデルの応答に依存します。
- 保存後のAPIリクエストからページ翻訳・選択翻訳に反映します。保存時に翻訳キャッシュを削除します。表示済みの訳文を更新するには、翻訳を停止し、原文に戻して再翻訳してください。

辞書のAPI形式は[PLaMo公式モデルカード](https://huggingface.co/pfnet/plamo-3-translate-8b-GGUF#translation-options)を参照しています。

### 操作・応答性の設定

「設定」の「翻訳の処理」「操作と表示」で、以下を個別にオン／オフできます。

| 設定 | 初期値 | 動作 |
| --- | --- | --- |
| 解析中も操作できるようにする | オン | DOM走査と優先順の計測を一定件数ごとに区切り、ブラウザへ制御を戻します。解析中も進捗パネル／ツールバーから停止できます。ブロック構造の判定も走査中に再利用します。 |
| 画面内の段落を先に翻訳 | オン | 同じ優先度の中で、開始時に見えている段落・画面に近い段落を先に処理します。 |
| 本文をメニュー・サイドバーより先に翻訳 | オン | 記事・本文の文章→本文内の表や折りたたみ見出し→その他→メニュー・サイドバーの順に処理します。範囲は狭めません。 |
| 本文だけを翻訳 | オフ | `main`・`role="main"`、なければ`article`を対象にします。入れ子の本文は重複処理しません。本文の目印がない場合はページ全体に戻ります。ポップアップでも切り替えられます。 |
| 選択直後の翻訳ボタン | オフ | 選択した文章の近くに「翻訳」を表示し、クリックすると選択翻訳します。入力欄・編集可能領域には表示しません。選択だけではAPIを呼びません。 |
| キーボードショートカット | オン | 下記の3操作を利用できます。オフの間は翻訳処理を起動しません。 |
| コピーボタン | オン | 原文パネルと選択翻訳の結果に表示します。ボタンを押した場合だけ、書式なしの文章をコピーします。エラーや未完了の訳文はコピー対象にしません。 |
| ホバーで原文を表示 | オン | 新しいページで使う既定値です。ポップアップからページ単位でも変更できます。 |
| キーボードで原文を確認 | オン | 訳文中のリンクへTabで移動すると原文を表示します。F2で原文パネルへ移動して選択・コピー・固定ができ、Escapeで元のリンクに戻ります。 |
| ページ内の進捗パネル | オン | オフでもツールバーで進捗を確認し、停止・復元できます。 |
| 進捗の読み上げ通知 | オン | 解析開始・25%の区切り・完了・停止・エラーをライブリージョンで通知します。秒数の更新は読み上げません。進捗パネルとは独立して切り替えられます。 |

ショートカットの初期値：

- **Alt+Shift+Y**：ページ翻訳／停止
- **Alt+Shift+U**：選択範囲を翻訳
- **Alt+Shift+O**：原文に戻す

Firefoxのアドオンマネージャーの「拡張機能のショートカットを管理」でキーを変更できます。選択翻訳のショートカットはトップフレームが対象です。iframe内では右クリックを使ってください。

処理範囲と優先順は次の翻訳開始から反映します。表示・操作の設定は開いているページにも反映します。選択ボタンを有効にした場合は、新しいページでも選択を検知するためcontent scriptを読み込みます。コピーには`clipboardWrite`権限を使い、HTTPページでも拡張のバックグラウンド経由で実行します。クリップボードの読み取り権限は使いません。

原文・選択訳文には言語情報と文字方向を指定し、拡張UIは日本語として扱います。設定画面は狭い幅で折り返し、OSの高コントラスト表示では標準のチェックボックスを使います。

設定画面の「接続を確認」は、入力中の接続先・APIキー・モデル・API形式で短いテスト翻訳を送信します。実測tokenizerを選んでいる場合はそのAPIも確認します。設定は保存せず、ページ本文や辞書は送信しません。テスト通信も全タブ共通キューを使い、応答のタイムアウトは最大15秒です。

設定には未保存表示と「変更を破棄」があり、未保存で閉じる際は確認します。保存では変更した項目だけを更新し、別画面での辞書・設定変更を保持します。同じ項目が別画面で変更されていた場合は保存を止めて通知します。選択翻訳パネルでは原文・訳文言語を入れ替えられ、「再翻訳」で実行します。

「実験的な機能」の「一時的なサーバーエラーを自動で再試行」は既定オフです。有効時はHTTP 429・502・503・504のみ最大2回再試行します。待機は通常0.5秒・1秒、`Retry-After`がある場合はその値（最大10秒）です。待機中は通信枠を解放し、停止操作で中断できます。認証エラー・接続失敗・タイムアウトは自動再試行しません。

実験設定の「同じ記事・表・メニューの段落をまとめる」は既定オンです。DOMの意味的な境界を使い、無関係なコンポーネントを混ぜずに送信します。各段落の復元とリンクの保持は個別に行います。翻訳する文章の意味を別のモデルで判定する機能ではありません。

「訳文をストリーミングで受信」は既定オフです。`stream: true`と`stream_options.include_usage: true`でSSEを受信します。選択翻訳では途中の文字列を表示し、コピーは完了後に有効にします。ページ本文は応答全体のマーカー・リンク構造を検証してから反映します。受信途中の切断は完成した訳文として扱わず、停止で受信も中断します。JSONを返すサーバーでも通常応答として処理できます。ストリーミングは生成そのものを速くする機能ではありません。

### 翻訳キャッシュと再訪時の復元

手動でページ翻訳した段落の原文・訳文を、既定で翻訳完了から30分間、拡張のバックグラウンドのメモリに保持します。リンク先から戻る、再読み込みする、同じURLを別タブで開く場合にも、原文と段落構造が一致する訳文を自動で復元します。復元したページでは、その訳文の言語設定も復元し、原文ホバーと「原文に戻す」を引き続き使えます。Firefox自身が履歴内にページを保持している場合は、表示済みの訳文がそのまま残ることもあります。

- キーはページURL（パス・クエリを含み、`#`以降を除く）、原文・訳文言語、段落全体の原文・タグ・ID・保護対象です。接続先・APIキー・モデル・API形式・文体・分割設定などが異なる結果は再利用しません。
- 復元ではAPIを呼びません。未翻訳・変更された段落や後から読み込まれる文章は、再度「ページを翻訳」を押すまで原文を表示します。DOM更新を監視する自動翻訳は行いません。
- 構造検証に成功した段落だけを保存します。失敗・停止したリクエストの結果と選択翻訳は保存しません。再利用によって保存期限は延長しません。
- 全タブ合計で原文・訳文などの文字列を最大約8MiB・2000段落保持し、上限を超えた場合は利用の古い段落から削除します。期限切れは利用時と1分ごとの掃除で削除します。大量のページでは期限前に削除されることがあります。
- 「接続設定」→「翻訳キャッシュ」で保存期間を0〜1440分に変更でき、0で無効になります。「キャッシュを削除」で全件削除できます。設定保存時、Firefox終了時、拡張の再読み込み時にも消えます。削除しても表示中の訳文はそのまま残ります。
- 翻訳キャッシュの原文・訳文・ページURLはディスクのストレージへ保存しません（後述のエラー記録は別管理です）。プライベートウィンドウでは保存・再利用しません。APIキーをcontent scriptへ渡しません。

### エラー記録

設定画面の「エラー記録を確認・JSON出力する」から、翻訳時のエラーを確認できます。原文（送信した段落・分割片・バッチ）、問題の応答、エラー詳細・スタック、発生時刻、拡張のバージョン、サイトのorigin、翻訳言語、接続先とモデル・分割などの設定を保存します。通信エラー、応答の異常、生成上限、HTML構造の検証失敗を記録し、再試行で回復した問題も残します。トークン計測など処理全体の失敗時には、対象リクエストの原文を記録します。

- `browser.storage.local` の専用領域に保存します。キャッシュの保存期間・無効化・削除、設定保存とは独立し、Firefox終了・拡張の再読み込み後も残ります。自動的な時間切れはありません。
- 最大100件・JSONで4MiB。超過時は古い記録から削除します。各文字列は32000文字までで、省略を明記します。
- APIキーは保存せず、原文・応答に同じキーが含まれる場合も除去します。ページURLはoriginだけを記録します。プライベートウィンドウと利用者による停止は記録しません。
- 一覧の詳細を開いて内容を確認し、「JSONを保存」で改善調査用に取り出せます。「エラー記録を全件削除」で記録だけを削除できます。自動送信はしません。原文や応答に個人情報が含まれることがあるため、共有前にJSONの内容を確認してください。

### キャッシュ内の翻訳履歴

ページ翻訳1回ごとに、開始時刻・サイトと翻訳言語・残存段落数・原文文字数・処理時間・API回数・再処理の有無・出力トークン数・API tok/s・生成 tok/s・初回受信時間を表示します。表示中は5秒ごとに更新し、「更新」でも読み直せます。リンクから翻訳元ページを開けます。

- 一覧の上に、現在の履歴の翻訳回数・残存段落数・原文文字数・累計処理時間・API応答数・出力トークン・速度・平均初回受信を表示します。速度は行ごとの単純平均ではなく、トークン数の合計÷対応する時間の合計です。初回受信は応答数で加重平均し、処理時間は各行の合計（同時処理も含む）です。共有API応答も行ごとに数えます。計測不能の応答がある場合、出力トークン・対応する速度は「—」になります。キャッシュから消えた履歴は合計からも除かれます。
- 段落数・文字数は**現在キャッシュに残っている範囲**です。同じ原文・構造の段落はキャッシュ上の1件として数えます。一部が期限切れや容量制限で消えた場合は残存件数が減り、すべて消えると履歴行も消えます。
- 処理時間はページ解析・順番待ち・入力計測を含み、最後にキャッシュへ保存したリクエストの完了までです。処理中も保存済みの分から表示します。時刻・処理時間・API回数・出力トークン数・速度は元の翻訳処理の記録です。
- **API tok/s**は`usage.completion_tokens`の合計÷API応答時間の合計です。入力処理・初回応答待ち・受信を含み、順番待ち・tokenize・再試行の待機は含みません。モデルの生成速度とは異なります。
- **生成 tok/s**はサーバーの`timings.predicted_n`合計÷`predicted_ms`合計（秒換算）です。時間計測値がない応答を含む場合は「—」にします。ストリームは複数トークンがまとめて届くことがあり、最初〜最後の受信時間から生成速度を推定すると過大になるため使用しません。
- **初回受信**は送信から最初の訳文を受け取るまでの平均です。API速度と生成速度の差が大きい場合、入力処理・初回応答待ちの負担を切り分ける参考になります。API回数に「再処理」がある場合は、バッチ破損・構造の再試行・生成上限による再分割の回数も確認できます。
- キャッシュからの再利用・再訪時の復元だけでは履歴を増やしません。選択翻訳・プライベートウィンドウ・キャッシュ無効時の処理は記録しません。
- 履歴もメモリ内だけに保持し、キャッシュ削除・設定保存・Firefox終了・拡張の再読み込みで消えます。「キャッシュと履歴を削除」は表示済みの訳文を変更しません。

設計の参考： [Immersive Translateの期限付きキャッシュ削除](https://immersivetranslate.com/en/docs/advanced/#cache-cleaning-cycle)は30日を既定とし、[Simple Translateの実装](https://github.com/sienori/simple-translate/blob/master/src/common/translate.ts)は原文・言語・翻訳サービスをキーにセッション内で成功結果を再利用します。この拡張では短時間のページ再訪を目的に、30分の期限と段落一致による復元を組み合わせています。

## ページ解析

1. 表示されているDOMを読み、段落・見出し・リスト項目・表のセルなどのブロック境界で翻訳単位を作ります。viewportの外でもレイアウトされている文章は対象です。
2. 句読点・空白・リンクを含む段落全体を、ID付きの最小限のHTMLとしてまとめて渡します。属性のない `span` は翻訳上の境界にしません。リンクのラベルだけでなく前後の文章も一緒に翻訳し、訳文の語順に合わせてリンクや書式要素を移動できます。リンクは元のDOM要素を再利用し、URL・属性・イベントリスナーを保持します。`br`・画像などは段落内の保護された参照として残し、前後の文章を一緒に翻訳します。独自のインライン要素も文章を抽出し、元の要素を保持します。インラインコードは `translate="no"` で保護します。読み上げ専用の `.sr-only` などは送信しません。
3. 応答のタグ・IDの一意性・入れ子・保護対象の不変性を検証します。`&copy;`・`&mdash;`などのHTML文字参照は文字として解釈し、任意のタグ・属性の挿入は認めません。段落の先頭・末尾の空白も保持します。構造が壊れた場合は同じ段落全体で1回再試行し、それでも失敗すればその段落を原文のまま残します。リンク前後の断片を個別翻訳して連結するフォールバックは行いません。長文は入力トークン上限に応じて分割し、タグを保持して結合します。
4. コードブロック・インラインコード・スクリプト・スタイル・フォーム入力・編集可能領域・SVG・数式・非表示要素・閉じた`details`の最初の`summary`以外・`translate="no"`・`.notranslate` を除外します。URLだけ・メールアドレスだけ・数字だけのテキストも対象外です。`lang` 属性が訳文と同じ要素や、明らかな日本語／韓国語の同言語翻訳も避けます。
5. 翻訳中にサイトが原文のテキスト・構造・リンク属性・段落の属性や言語を更新した場合、その段落への適用を見送ります。モデルのHTMLは検証済みのテキストと既存要素への参照に変換し、任意のタグや属性をページに挿入しません。要素を動かさずに反映できる場合は既存のテキストノードだけを更新し、元の`span`・フォーカス・サイトが持つノード参照を保持します。原文復元時は元の要素・順序・テキストを復元し、コードや入力欄などの保護領域内でサイトが更新した状態は維持します。絵文字の結合文字や文字方向を指定する制御文字も原文から削除しません。

通常のHTTP/HTTPSページが対象です。Firefoxの制限ページ（`about:`、Mozillaの一部ページなど）、内蔵PDFビューア、closed Shadow DOMには対応しません。open Shadow DOMはスロットに割り当てられた文章も走査し、表示されない未割り当てのlight DOMは対象にしません。ページ全体翻訳ではiframe内を走査しませんが、iframe内で選択した文章は右クリックから翻訳できます。CSSの疑似要素・画像中の文字・属性値は変更しません。

全Webページ上での手動実行・保存済み訳文の復元と任意のローカルAPIへの接続のため、HTTP/HTTPSのホスト権限を指定しています。各ページで小さなスクリプトがキャッシュと選択ボタン設定を確認し、翻訳用のcontent scriptは手動操作時・キャッシュの復元時・選択ボタンが有効な場合に注入します。

解析・DOM保持の参考： [Firefoxの翻訳実装](https://github.com/mozilla-firefox/firefox/blob/main/toolkit/components/translations/content/translations-document.sys.mjs)、[HTMLのtranslate属性](https://developer.mozilla.org/en-US/docs/Web/HTML/Global_attributes/translate)。

## 長文の分割

既定は、公式PLaMo tokenizerのbyte fallbackを踏まえた **UTF-8バイト数による安全側のトークン見積もり** です。厳密なtokenizer計測ではなく、実際より小さなチャンクになることがあります。追加のサーバAPIを要求しないため、この方式を初期値にしています。

実測する場合は、設定の「トークンの数え方」を llama.cpp または vLLM に変更してください。指定の `/tokenize` に、llama.cppでは `{ "content": "…", "add_special": false }`、vLLMでは `{ "model": "…", "prompt": "…", "add_special_tokens": false }` を送り、返った `tokens.length` または `count` を使います。サーバがそのAPIを提供している必要があります。実測に失敗した場合はエラーを表示します。MLX標準サーバーはこの`/tokenize`形式を提供しないため、通常はUTF-8バイト数の見積もりを使ってください。

入力上限内になるよう段落→文末→空白→Unicodeコードポイントの順で境界を選びます。既定のバイト数見積もりでは、残り全文を繰り返し変換せずに走査し、HTMLのエスケープとタグの分も予算に含めます。段落全体が上限内なら細分化せず、要素ごとの追加計測を省きます。文字や元の空白を欠落させず、サロゲートペアも分断しません。出力の `finish_reason: "length"` は完成した訳文として採用せず、原文をさらに分割して再リクエストします。トークン計測を含むすべてのリクエストは全タブ共通キューを通します。

設定・辞書の検証結果は変更まで再利用し、同時に始まる翻訳でもストレージ読出しを共有します。実測tokenizerでは、同じ翻訳リクエスト内の重複計測を最大128件・保持文字列約1MiBまで再利用します。翻訳リクエストが終われば破棄し、別のリクエストやモデルの計測値とは共有しません。削除されたページ要素への翻訳記録は、次の手動解析で解放します。

## 0.1.3の処理改善

実験設定で、表示位置に応じた未送信段落の再選択・処理中通信の共有・原文に現れる辞書項目の絞り込みを個別に切り替えられます。既定はオンです。画面内と約1.5画面先までを優先し、残りのページも順次処理します。スクロールでは通信を中止しません。見出しと直後の文章、表の行、リスト項目を保ち、短い地域リストの小節や隣接する図版キャプションはまとめます。記事本文の節は混ぜません。最初は約1200予算・最大4単位、近傍は約2400・最大16単位、遠方は入力上限・最大64単位です。収まる表の行などは単位数の目安よりまとまりを優先します。

送信前に更新・非表示となった候補を除き、同じTextノードをサイトが更新した場合は次の手動翻訳で再確認します。属性だけの変更や拡張自身の翻訳では再翻訳しません。全体を再収集するMutationObserverは追加していません。

通信共有は実際の本文・言語・Context・辞書・接続設定・タイムアウト・再試行方針・キャッシュ世代が一致する処理だけが対象です。通常とプライベートの通信は分け、最後の利用者が停止したときだけ元の通信を中止します。共有対象は処理中だけで、完了後の再利用は既存キャッシュの設定に従います。履歴のAPI応答数には共有分を含め、「うち共有」を併記します。

固定の翻訳指示を短縮し、HTMLの辞書照合にはタグやIDでなく原文テキストを使います。段落とリンクの構造検証、出力上限8096、全タブ共通の既定並列数1を維持します。
