# Kotoba — Local Translate

ローカルで動かす PLaMo 3 Translate の OpenAI 互換エンドポイントを使う、個人用の Firefox 拡張です。ビルドなしで `extension/` を読み込めます。

## Firefox に読み込む

1. Firefox で `about:debugging#/runtime/this-firefox` を開きます。
2. 「一時的なアドオンを読み込む」から、このリポジトリの `extension/manifest.json` を選びます。
3. ツールバーの Kotoba →「接続設定」で、起動中の翻訳サーバを設定します。

一時的なアドオンは Firefox 終了時に外れます。再起動後は読み込み直してください。署名や配布の仕組みは含めていません。

更新時は拡張に加えて、翻訳するページも再読み込みしてください。ページ内に古いスクリプトが残っている場合は、ポップアップに「ページを再読み込み」を表示します。ZIPから読み込んでいる場合は、更新したZIPを読み込み直す必要があります。

開発用に別プロファイルの Firefox を起動する場合：

```sh
npm ci
npm start
```

## 接続設定

| 設定 | 初期値 |
| --- | --- |
| エンドポイントURL | `http://127.0.0.1` |
| ポート | `8000` |
| Chat Completions パス | `/v1/chat/completions` |
| APIキー | 空欄 |
| モデル名 | `plamo-translate` |
| 翻訳パラメータ形式 | トップレベル（依頼のbody形式） |
| 同時リクエスト | **全タブ共通で1**（設定で1〜8） |
| 入力の分割上限 | 3000トークン（設定で128〜3900） |
| 出力上限 | **`max_tokens: 8096`** |
| タイムアウト | 180秒（設定で変更可能） |

上の例では `http://127.0.0.1:8000/v1/chat/completions` に送信します。URLにはサーバのベースURL、パスにはAPIのパスを入れてください。ベースURLにパスがあれば、その後ろにAPIパスを連結します。ポート欄を空にするとURL内のポートを使います。

APIキーを設定すると `Authorization: Bearer <APIキー>` を付けます。入力時の `Bearer ` 接頭辞は取り除くため、キーだけでも入力できます。接続先以外へのリダイレクトは追跡しません。APIキーを含む設定は `browser.storage.local` に保存し、Webページやcontent scriptには渡しません。

### API形式

初期値は依頼されたトップレベル形式です。

```json
{
  "model": "plamo-translate",
  "messages": [{ "role": "user", "content": "Text to translate." }],
  "context": "This text is from a web page on https://example.com. Translate it as part of the website, preserving the meaning and natural flow of complete sentences.",
  "form": "",
  "source_lang": "en",
  "target_lang": "ja",
  "max_tokens": 8096,
  "stream": false,
  "temperature": 0,
  "use_glossary": false
}
```

`context` はWebサイトの文章を翻訳する旨と、翻訳対象ページの **origin（scheme + domain + ポート）** を含みます。HTMLを含む段落では、段落全体の自然な語順を保ち、タグ・リンクのID・コードを保持する条件も加えます。パス・クエリ・ページタイトルは渡しません。原文言語の「自動判定」では `source_lang` を省略します。

公式の llama.cpp / vLLM のチャットテンプレートを使う場合は、設定の「chat_template_kwargs」を選びます。`source_lang`、`target_lang`、`context`、`form` を `chat_template_kwargs` に入れ、公式例のstopトークンを指定します。専用翻訳モデルなので、翻訳の指示を `system` メッセージに入れません。

参照： [PLaMo 3 Translate 公式モデルカード](https://huggingface.co/pfnet/plamo-3-translate-8b-GGUF#translating-with-the-api)。公式では `max_tokens` は訳文の生成上限であり、入力と出力の合計はサーバのコンテキスト長にも収める必要があります。入力上限3000と出力8096を使う場合、サーバのコンテキスト長は制御情報も含めて十分な値（例：16384以上）を確保してください。

## 使い方

- **ページ翻訳**：ツールバーで原文・訳文の言語を選び「ページを翻訳」。言語はそのページの状態として保持します。初期値だけ接続設定で指定できます。
- **まとめて翻訳**：既定でオン。短い段落をID付きマーカーで囲み、入力トークン上限内でまとめて送信します。返却結果のマーカーと各段落のHTML構造を検証して元の位置に戻します。マーカーの欠落・重複や構造の破損、生成上限への到達時は、段落単位の翻訳に切り替えます。ポップアップの「複数の段落をまとめて翻訳」でオフにできます。設定は全ページ共通で保存され、次回の翻訳開始から反映されます。
- **原文表示**：訳文にマウスを280ms重ねると、対象の段落を薄い水色で強調し、原文を表示します。同じ段落内では表示を維持し、ポップオーバー内へ移動して原文を選択できます。「固定」で表示を維持できます。外側のクリック・スクロール・Escapeで閉じます。ツールバーでホバー表示を切り替えられます。
- **選択翻訳**：文章を選択し、右クリック →「選択したテキストを翻訳」。ツールバーの「選択範囲を翻訳」でも使えます。選択範囲の近くに結果を表示し、パネルで言語を変更して再翻訳できます。選択翻訳はページの文章を差し替えません。
- **進捗**：ツールバーとページ内パネルで、進捗率・完了段落数・経過秒数を表示します。進捗率は翻訳対象の原文文字数に対する処理済み文字数で、長文の分割リクエストの完了も反映します。トークン生成の進捗率ではありません。ページ内パネルを閉じても翻訳は続きます。
- **停止**：処理中・待機中のAPIリクエストを中断し、遅れて返った訳文の適用を防ぎます。
- **原文に戻す**：翻訳部分を復元します。サイト自身が更新した箇所には古い原文を上書きしません。
- **追加で読み込まれた文章**：再度「ページを翻訳」を押してください。表示中の翻訳済みノードはそのままに、新しい文章を処理します。原文に戻した後の再翻訳では、APIを再度呼びます。

ページ読み込み時の自動翻訳、DOM更新を監視する自動翻訳、翻訳結果のキャッシュはありません。原文復元に必要な原文・訳文は、そのページが開いている間だけメモリに保持します。原文・訳文をストレージには保存しません。言語設定はリロードや別URLへの移動で初期値に戻ります。

## ページ解析

1. 表示されているDOMを読み、段落・見出し・リスト項目・表のセルなどのブロック境界で翻訳単位を作ります。viewportの外でもレイアウトされている文章は対象です。
2. 句読点・空白・リンクを含む段落全体を、ID付きの最小限のHTMLとしてまとめて渡します。属性のない `span` は翻訳上の境界にしません。リンクのラベルだけでなく前後の文章も一緒に翻訳し、訳文の語順に合わせてリンクや書式要素を移動できます。リンクは元のDOM要素を再利用し、URL・属性・イベントリスナーを保持します。インラインコードは `translate="no"` で保護します。読み上げ専用の `.sr-only` などは送信しません。
3. 応答のタグ・IDの一意性・入れ子・保護対象の不変性を検証します。構造が壊れた場合は同じ段落全体で1回再試行し、それでも失敗すればその段落を原文のまま残します。リンク前後の断片を個別翻訳して連結するフォールバックは行いません。長文は入力トークン上限に応じて分割し、タグを保持して結合します。
4. コードブロック・インラインコード・スクリプト・スタイル・フォーム入力・編集可能領域・SVG・数式・非表示要素・`translate="no"`・`.notranslate` を除外します。URLだけ・メールアドレスだけ・数字だけのテキストも対象外です。`lang` 属性が訳文と同じ要素や、明らかな日本語／韓国語の同言語翻訳も避けます。
5. 翻訳中にサイトが原文のDOMを更新した場合、その段落への適用を見送ります。モデルのHTMLは検証済みのテキストと既存要素への参照に変換し、任意のタグや属性をページに挿入しません。原文復元時は元の要素・順序・テキストを復元します。

通常のHTTP/HTTPSページが対象です。Firefoxの制限ページ（`about:`、Mozillaの一部ページなど）、内蔵PDFビューア、closed Shadow DOMには対応しません。open Shadow DOMは走査します。ページ全体翻訳ではiframe内を走査しませんが、iframe内で選択した文章は右クリックから翻訳できます。CSSの疑似要素・画像中の文字・属性値は変更しません。

全Webページ上での手動実行と任意のローカルAPIへの接続のため、HTTP/HTTPSのホスト権限を指定しています。content scriptはユーザー操作時に注入します。

## 長文の分割

既定は、公式PLaMo tokenizerのbyte fallbackを踏まえた **UTF-8バイト数による安全側のトークン見積もり** です。厳密なtokenizer計測ではなく、実際より小さなチャンクになることがあります。追加のサーバAPIを要求しないため、この方式を初期値にしています。

実測する場合は、設定の「トークンの数え方」を llama.cpp または vLLM に変更してください。指定の `/tokenize` に、llama.cppでは `{ "content": "…", "add_special": false }`、vLLMでは `{ "model": "…", "prompt": "…", "add_special_tokens": false }` を送り、返った `tokens.length` または `count` を使います。サーバがそのAPIを提供している必要があります。実測に失敗した場合はエラーを表示します。

入力上限内になるよう段落→文末→空白→Unicodeコードポイントの順で境界を選びます。文字や元の空白を欠落させず、サロゲートペアも分断しません。出力の `finish_reason: "length"` は完成した訳文として採用せず、原文をさらに分割して再リクエストします。トークン計測を含むすべてのリクエストは全タブ共通キューを通します。

## 確認・パッケージ化

```sh
npm test               # DOMの保持、分割、API形式、キャンセル、キューなど
npm run lint           # web-extによる拡張の検証
npm run test:firefox    # 一時プロファイルのFirefox + ローカル模擬API
npm run build          # artifacts/ に読み込み用ZIPを生成
```

`test:firefox` と `start` はmacOSの `/Applications/Firefox.app` を前提にしています。smoke testは `FIREFOX` 環境変数で実行ファイルを変更できます。smoke testは模擬応答による動作確認で、実モデルの翻訳品質や手元のサーバとの接続は別途確認してください。
